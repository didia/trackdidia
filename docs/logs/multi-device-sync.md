- 2026-10-28: External review fixes: the native backup folder check judges the `backups` / `backups-dev` directory that receives the database (a symlink there is refused, an existing marked folder is refused, the resolved path must be `<root>/<name>`; `prune_backups` too; refusals are typed `overlaps_sync_folder` and reach Settings and the `/sync` safety backup); the encoder refuses an uncompressed body over the decoder's 512 MiB cap (`body_too_large`, persistent `too_large`, no IPC), so an accepted publish is always readable.
- 2026-10-28: Adopted the revised engine contract: the folder transport implements publish fencing (`PublishMeta.engineId` / `publishSeq`: one FIFO queue for the whole operation plus a commit-time check that rejects an older sequence with `stale_publish` and writes nothing); `/sync` has French copy and rendering for the `pending_unpublished_domain` note, the `pending` peer state, a halted first merge (run-wide safety-backup reason with a link to Settings) and a publish replaced by a newer one; tests render every issue code and peer state.
- 2026-10-27: Review fixes: a backup is never written to the shared GTD folder (picker, `createBackup`, app-wide banner, Sync now precheck and the native `ensure_backup_dir` marker check, with a typed `BackupDestinationError`); backup tags come from the native device-id file, never from a copied database's `sync_identity`; the encoder enforces the 16 MiB line cap (persistent `too_large`); `SyncTransportError.reason` lets `/sync` tell a never-prepared folder from an unmounted one; French run errors; the enable warning says not to use or edit the app (quitting is safe); limits documented (disable keeps tracking installed, minimum system for compression, 30 s vs 45 s timeouts).
- 2026-10-27: Bundle, folder transport and minimal `/sync` page (experimental, debug-gated, manual only, personal profile only): `src/lib/sync/bundle.ts` encodes a change set as a preamble line plus gzip JSON lines with header counts (native `CompressionStream`, uncompressed fallback, 8 x 64 MiB inflate cap, typed `SyncBundleError`), `transport-folder.ts` implements `SyncTransport` per folder role over the folder commands (error mapping to retryable `unreachable` / `timeout` and non-retryable `SyncTransportFailure` kinds `configuration`, `too_large`, `unsupported`, `internal`; publish timeout reconciled through the device's own manifest; serialized publishes), and `sync-service.ts` enables and disables sync (folders prepared with each other as `otherFolderDir`, identity, capture backfill, setting) and builds the engine with a per-device safety backup. Four device-local settings (`multiDeviceSyncEnabled`, `syncProfile`, `syncGtdFolderDir`, `syncDeviceName`). Settings card (debug mode only), `/sync` page and nav entry (debug mode and `multiDeviceSyncEnabled`), `createBackup(kind, { deviceId })` with per-device names whenever sync is enabled. Measured bundle sizes and the unchunked enable backfill timing are recorded in [storage-and-backups.md](../storage-and-backups.md#sync-bundle-format-and-folder-transport) and the page.
